🧬 Biology — the mechanism this investigation models When embryonic cells of two types are mixed, they spontaneously unmix — one type engulfing the other — driven purely by differences in how strongly like and unlike cells…

When embryonic cells of two types are mixed, they spontaneously unmix — one type engulfing the other — driven purely by differences in how strongly like and unlike cells adhere. This is the differential adhesion hypothesis, and it is one of the oldest and cleanest examples of self-organisation in tissue: no cell knows the target pattern, yet the pattern reliably emerges from local adhesive preference plus random motion.

The modelling question is that every class of cell-based model claims to capture this. A cellular automaton represents a cell as a lattice site; a Potts model as a set of sites; an overlapping-spheres model as a particle; a Voronoi model as a tessellation region; a vertex model as a polygon. All five can be tuned to sort. Osborne et al. asked whether they sort the SAME WAY — and found they do not: CA, CP and VM reach full engulfment, while OS and VT stall at a local energy minimum and, given long enough, fully separate instead. Random cell motion is what lets a model escape that minimum, which is why the noise multiplier k_pert is the axis they sweep.

Our reproduction targets that specific claim — the fractional boundary length trajectory, which measures how much interface remains between unlike cells as sorting proceeds.

🔬 Scientific argument A process-bigraph wrapper over PyChaste can reproduce a published Chaste result quantitatively — but only where the upstream Python bindings cover…

Main claim. A process-bigraph wrapper over PyChaste can reproduce a published Chaste result quantitatively — but only where the upstream Python bindings cover the classes the publication used; binding coverage, not modelling fidelity, is the binding constraint.

Caveats

  • No simulations have been run yet. Every claim here is a design-time expectation.
  • The paper's repo ships with paper parameters COMMENTED OUT and short CI values active (cell sorting: t_end 11.0 in-repo vs 100 in the paper). The C++ baseline is only a baseline if those blocks are restored first — a silent way to produce a wrong reference.
  • Chaste under amd64 emulation on Apple Silicon is slow. The paper's sorting runs are 20x20 cells to t=100 across 5 models x 10 seeds x 9 k_pert values; the full Fig 3 sweep is likely infeasible on this laptop and may need the Mac mini or a reduced sweep.
  • The paper's own figures are NOT the reference — the authors' C++ output is. Divergence between our PyChaste run and their C++ run is the measurement; divergence between either and the published PNG is not interpretable.

Question. Can we build Chaste plus the authors' CellBasedComparison2017 project from source and regenerate the cell-sorting output of Osborne et al. 2017 — producing per-model heterotypicboundary.dat trajectories that serve as the ground truth for every later study?

Hypothesis. The project builds against modern mainline Chaste (its copyright headers run to 2021 and its CI claims continuous testing), and once the paper-parameter blocks are restored the five sorting sims reproduce Fig 2 qualitatively — CA, CP and VM reaching engulfment; OS and VT stalling at a local minimum.

Objective. Build Chaste + CellBasedComparison2017, restore the paper parameters that the repo ships commented out, run TestCellSortingLiteratePaper for all five models across 10 seeds, and archive the resulting heterotypicboundary.dat files as the investigation's reference dataset.

Background

This study exists because the expert asked for a careful comparison against existing Chaste results, and chose regenerated C++ output over published figures as the reference.

The critical trap is documented in the authors' own source: every test file ships with the paper parameters COMMENTED OUT and short continuous-integration values active. For cell sorting, M_TIME_FOR_SIMULATION is 11.0 in the repo versus 100 in the paper. Running the suite as-cloned produces a plausible-looking but wrong baseline — the single highest-risk silent failure in this investigation. Restoring those blocks is step one, and the diff must be recorded.

The build is the other risk. The project's CMakeLists declares find_package(Chaste COMPONENTS cell_based crypt), so the crypt component must be built even though the sorting case study does not use it. The paper pins historical Chaste branches (paper/CellBasedComparison, paper/CellBasedComparison18) against Oxford servers that are no longer the live mirror; we build against the GitHub mirror's develop and record the commit.

Output lands in $CHASTE_TEST_OUTPUT/CellSorting/{Ca,Potts,Node,Mesh,Vertex}. The measure the investigation turns on is heterotypicboundary.dat, whose four columns are (heterotypic_boundary_length, total_shared_edges_length, num_heterotypic_pairs, total_num_pairs). The paper's fractional boundary length is column 1 / column 2 — the writer does NOT divide, so the reduction is ours to perform and to test.

Question. Can pbg-chaste's ChasteSimulationProcess be extended to cover the four model classes the paper's sorting study needs and PyChaste can reach — Potts (CP), overlapping spheres (OS), Voronoi-with-ghost-nodes (VT) and vertex (VM) — emitting fractional boundary length as a first-class observable?

Hypothesis. All four are reachable with mainline PyChaste classes alone. The probe confirmed every required population, force, update rule, mesh generator and the HeterotypicBoundaryLengthWriter are bound; the work is wrapper architecture, not missing bindings.

Objective. Extend the wrapper to dispatch OnLatticeSimulation alongside OffLatticeSimulation, add Potts and ghost-node populations, two-cell-type labelling, the differential-adhesion forces and update rules, and surface heterotypic boundary length on an output port.

Background

The current wrapper is a 12-combination demo of a single simulation class. Three structural changes are needed, and the first is the one that breaks the existing design.

(1) OnLatticeSimulation. `_chaste_server.py` hardcodes OffLatticeSimulation2_2, and the force/_apply_stiffness abstraction does not generalise: on-lattice populations take update rules via AddUpdateRule, not forces via AddForce. This needs a real dispatch seam, not another branch in the existing if-chain.

(2) Ghost nodes for VT. The paper's VT is MeshBasedCellPopulationWithGhostNodes with 20 ghost layers; the wrapper's `mesh` population calls HoneycombMeshGenerator(w, h) with no ghost argument and is therefore NOT the paper's VT. The output extractor also assumes every location index is a real cell, so it must learn to filter GetGhostNodeIndices — otherwise ghosts are silently counted as cells and every population-level number is wrong.

(3) Two cell types. The paper relaxes to steady state, then labels ~50% of cells with CellLabel and runs on. The wrapper has no notion of cell type or labelling at all.

Scope note: CA is deliberately excluded. Its DifferentialAdhesionCaSwitchingUpdateRule is custom to the paper's repo, and AbstractCaSwitchingUpdateRule_2 exposes no constructor to subclass — see the investigation's decisions_needed. CaBasedCellPopulation itself IS bound, so the CA population may still be constructed; only its adhesion-driven switching is out of reach.

Two landmines from the existing code carry over: every Chaste object must be retained in _KEEP or the next call aborts with "pure virtual method called", and state must be extracted before any teardown because TearDownNotebookTest segfaults after a real run.

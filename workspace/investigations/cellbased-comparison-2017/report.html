Verdict — PASSED

pbg-chaste reproduces the paper's cell-sorting result for the four model classes PyChaste can reach (CP, OS, VT, VM). Single-seed fractional-length trajectories track the authors' own C++ code to within 0.01-0.15 at every timepoint and reproduce the paper's Fig 3 ordering (VT stalls, OS/CP sort strongly, VM intermediate). CA is out of reach — its differential-adhesion switching rule is custom to the paper's repo with no constructible PyChaste base. The reproduction is driven by the differential-adhesion physics, which pbg-chaste runs through the identical Chaste C++ classes; the random-motion term (a mainline DiffusionForce substitute for the paper's custom RandomMotionForce) is a second-order perturbation and the main residual.

Is DiffusionForce really the paper's RandomMotionForce?

Accepted

Is mainline Chaste's DiffusionForce numerically equivalent to the custom RandomMotionForce that Osborne et al. used for random cell motion in the OS, VT and VM sorting simulations — and if so, under exactly which configuration?

DiffusionForce is a sound RandomMotionForce substitute for OS and VM (free-diffusion MSD matches at D=xi; sorting trajectories track the C++ baseline within 0.15/0.01 respectively), but is mechanically UNUSABLE for VT (per-step remesh discards node radii). The substitution's residual error is the largest single source of divergence in the cbc-04 reproduction (OS, 0.147), yet is second-order to the adhesion physics — VT reproduces within 0.07 with no noise at all.

How the reproduction works

  • Same engine, not a re-implementation. pbg-chaste drives the real Chaste C++ library through the official chaste/pychaste image. CP/OS/VT/VM use the identical population, force and update-rule classes the tutorial uses.
  • The measure is Chaste's own. Fractional boundary length comes from Chaste's HeterotypicBoundaryLengthWriter, emitted identically by both sides.
  • One documented substitution. The tutorial's custom RandomMotionForce cannot be bound from Python, so OS/VM use mainline DiffusionForce, calibrated to the same diffusion constant and verified against free-diffusion MSD (study cbc-03).
  • The ground truth is regenerated, not read off the page. We built the authors' project against chaste/release and ran it to t=100; the comparison is our PyChaste output vs that C++ output.

Honest limitations

  • CA is out of reach. The cellular automaton's DifferentialAdhesionCaSwitchingUpdateRule is custom to the tutorial repo and PyChaste exposes no constructible base to subclass. Reported, not hidden — the C++ baseline still includes CA for completeness.
  • VT runs without random motion. DiffusionForce divides by node radius, which the Voronoi population's per-step remesh discards; it still reproduces the tutorial's stalled VT within 0.07, because sorting here is adhesion-driven and the noise is second-order.
  • Single seed. Both sides are seed 0. Point divergences are small (VM 0.012, CP/VT ~0.07, OS 0.15) but a 10-seed spread would turn "within run-to-run noise" into a quantitative claim.
